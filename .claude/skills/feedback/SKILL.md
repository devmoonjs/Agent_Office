# /feedback <파일 또는 디렉토리 경로>

지정된 코드를 리뷰하고 결과를 `30-Feedback/code-review/`에 저장한다.

## 절차

1. **대상 파악**: 경로의 코드를 읽는다. 디렉토리면 최근 변경된 파일 위주로 (git이 있으면 `git log --since='7 days ago' --name-only`로 우선순위 결정).
2. **리뷰 관점** (순서대로):
   - **보안** (CLAUDE.md 체크리스트): SQL injection(파라미터 바인딩 여부), XSS(이스케이프), JWT(시크릿 하드코딩/payload 민감정보), 환경변수·시크릿 노출, 에러 응답의 내부 정보 노출, 인증/인가 누락
   - **정확성**: 엣지 케이스, null/undefined 처리, 경합 조건
   - **유지보수성**: 중복, 과도한 복잡도, 네이밍
3. **결과 작성**: `30-Feedback/code-review/<날짜>-<대상이름>.md` — **CLAUDE.md "문서 스타일" 규정 적용** (기술문서 톤, 이모지 금지)
   - 심각도 표기: `[Critical]` / `[Major]` / `[Minor]` 텍스트 라벨
   - 모든 지적은 3요소 구조: 근거(`파일:라인` + 코드 인용) / failure mode(방치 시 발생 조건과 결과) / 개선안(코드 스케치 수준)
   - 잘한 패턴 1개 이상 짚기 — 반복할 가치가 있으면 `/wiki-add` 후보로 표시
4. **보고**: critical 항목 우선으로 요약 보고.

## 규칙

- 지적만 나열하지 말 것 — 각 항목에 "어떻게 고치는지" 코드 수준 제안 포함
- 코드를 직접 수정하지 않는다 (리뷰만). 수정은 사용자가 요청할 때만
