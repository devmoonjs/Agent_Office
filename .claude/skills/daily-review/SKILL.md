# /daily-review [YYYY-MM-DD]

일일 코드 학습 루프를 실행한다. 인자가 없으면 **어제** 날짜.

## 절차

1. **수집**: 두 단계로 실행한다
   - `bash 90-Meta/scripts/vault_snapshot.sh [날짜]` — vault 자체의 미커밋 작업분을 해당 날짜 커밋으로 스냅샷 (변경 없으면 자동 생략)
   - `bash 90-Meta/scripts/collect_diffs.sh [날짜]` 실행. 출력된 파일 경로(`.cache/diffs/<날짜>.md`)를 읽는다.
   - my_jarvis(이 vault)의 변경 분석 시 관점: 하네스/에이전트 설계 변화(skill, 템플릿, 스크립트, 스키마)가 분석 대상이다. 노트 본문(Daily/위키 등 에이전트 생성물)의 diff는 요약만 하고 리뷰 대상에서 제외한다
   - 총 커밋이 0이면 `10-Daily/<날짜>.md`에 "커밋 없음" 한 줄 노트만 만들고 종료.
2. **분석**: 수집된 diff를 읽고 분류한다 — 새 기술/패턴 도입, 리팩토링, 버그 수정, 설정 변경. 커밋 메시지와 실제 diff 내용이 일치하는지도 본다.
3. **출력물 2종 작성** — 같은 분석에서 용도가 다른 두 문서를 생성한다:

   **(A) 프로젝트별 변경 보고서** (업무 보고용): repo마다 `15-Reports/<repo명>/<날짜>.md`를 `90-Meta/templates/change-report.md` 구조로 생성
   - 독자는 비개발 결재자/팀장. 기능·업무 관점으로 "무엇이 달라지는가"를 쓴다. 코드 인용·파일 경로 금지, 기술 상세는 학습 문서 링크로 대체
   - 변경 내역 표의 구분: 신규 / 개선 / 수정 / 문서. 근거 열에 PR 번호 또는 커밋 해시
   - 리스크 항목에는 학습 문서의 Critical/Major 중 **배포·운영에 영향 있는 것만** 비기술 언어로 번역해 올린다 (예: "보고서 삭제 기능에 접근 제한이 없어 외부 노출 시 데이터 손실 위험")

   **(B) 학습 문서**: `90-Meta/templates/daily.md` 템플릿 구조로 `10-Daily/<날짜>.md` 생성. **CLAUDE.md의 "문서 스타일" 규정을 엄격히 적용한다** (기술문서 톤, 메커니즘 수준 설명, 정량적 근거, 코드 인용 필수). 상세 분석과 리뷰는 **레포별로 그룹핑**한다:
   - **개요**: 변경의 성격 요약 + repo별 규모 표
   - **변경 상세 분석**: 커밋 단위로 목적/구현 분석. 데이터 흐름(어디서 fetch → 어떻게 가공 → 어디에 렌더), 상태 전이, 실행 시점(mount/dependency 변경/interval)을 추적해 기술. 핵심 diff를 `파일:라인`과 함께 인용
   - **학습 항목**: 식별된 기술 요소 표 + 위키 링크
   - **리뷰**: `[Critical]` `[Major]` `[Minor]` 라벨. 각 항목은 근거(코드 인용), failure mode(방치 시 발생 조건과 결과), 개선안(코드 스케치 수준) 3요소를 갖춘다. CLAUDE.md 보안 체크리스트(SQL injection, XSS, JWT, 시크릿, 에러 노출) 적용
   - **보안 점검 결과**: 체크리스트 통과 여부 명시
   - **액션 아이템**: 우선순위 표, 대상 파일/함수 단위 명시
4. **위키 환류**: "배운 것"의 각 개념에 대해 `20-Wiki/` 아래 해당 분류(concepts/patterns/tools)에 노트가 없으면 `90-Meta/templates/wiki-note.md` 형식으로 스텁 생성 (frontmatter `source`에 커밋 해시 기록, `confidence: low`). 새 노트는 `20-Wiki/MOC-llm.md`의 해당 섹션에 등록.
5. **보고**: 생성한 파일 목록(보고서 N건 + 학습 문서 1건 + 위키 노트)과 repo별 핵심 1줄 요약, Critical 발견 시 최우선 보고.

## 규칙

- diff에 `[REDACTED]` 마커가 보이면 Daily 노트에 "⚠️ 보안 경고" 섹션으로 어떤 파일에서 시크릿 의심 패턴이 나왔는지 보고 (값은 절대 기록 금지)
- 머지 커밋은 diff가 비어 있을 수 있음 — 원 커밋(PR 본문 커밋)을 기준으로 분석
- 노트는 한국어, 기술 용어는 영문 유지
